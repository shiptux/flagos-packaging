测试环境

先说清楚测到了哪一步

NVIDIA 手上的卡就一块 A100，装在 Ubuntu 上。所以 NVIDIA/CUDA 这块（装、导入、算子数值）是在 deb 链路上测的，测得比较透。
openEuler RPM 这边，装和编译早就验过了。openEuler 上带 N 卡的环境之前在平台上不好弄，今天刚打通，就在开会前。有了这套，整个流程（打包、安装、带卡跑）就能在 NVIDIA 上完整走一遍了。这块我们自己推进。
想请社区帮的

NVIDIA 这套我们能自己验证，但其他后端、其他卡（国产 GPU 之类）手上就没有了。这块要是社区能帮忙提供环境、或牵个线找到对应厂商，就更好了，openEuler 上的多后端我们能一起往前推。

想和社区商量的几件事

  1. 正式入仓怎么走

    打算挂 sig-AI 提软件包引入。有个前提：src-openeuler 的 spec 得指向能下载的发布 tarball，也就是 FlagOS 各组件先得打正式 release tag。这块的流程想听听社区的经验。

  2. CUDA 和 SDK 在 openEuler 上怎么管理

    openEuler 是有 CUDA 镜像的（现在是 CUDA 13）。真正要研究的是 CUDA 和相关 SDK 在 openEuler 上怎么装、怎么管。另外我们自己也得摸清楚，到底哪些 C++ 组件依赖 CUDA 12、依赖有多深，先把这个具体问题找出来。

  3. 几个缺的依赖，想听听社区的做法

    typer、hydra-core 这几个 Python 库 openEuler 源里还没有。说实话我们还没想好怎么弄，随包带进去、还是走 EUR，就想先听听社区一般怎么处理。（顺带一提，现在 openEuler 的适配都是在 FlagOS 自己的 CI 里跑的。）
